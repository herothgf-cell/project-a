## 이 세션에서 실행한 검증
기존 기준선: 구문 및 Node 33/33, 오프라인 Chromium 검사 8묶음.
새 기능: 25개 실패 테스트를 먼저 확인한 뒤 구현했다. 자체 검토 과정에서 추가한 4개 회귀 조건도 실패 → 수정 → 성공으로 검증했다.
최종 로컬: `npm run check` 성공, `npm test` 62/62 성공.
기존 브라우저 검사 8묶음 성공. 새 기연 검사 7묶음 성공: 3계열 조사/시험/수락/전승/오의/도감; 390×844, 360×640, 844×390의 조작 겹침·멀티터치·취소·오의; reduced-motion 비경 렌더. 페이지 오류 0.

브라우저 검사는 DOM 버튼/키보드/실제 터치 이벤트를 사용한다. 테스트용으로 모델의 위치·진행·적 예고를 준비한다. 일반 유저의 완전 무보조 플레이를 대신하는 검증은 아니다. 세 계열의 전체 3장 진행은 별도 시뮬레이션에서 상호작용과 공격 호출로 엔딩까지 검증했다.
로컬 브라우저는 HTTP 탐색 제한 때문에 인라인 문서와 저장 shim을 사용한다. 실제 HTTP/브라우저 localStorage 검사는 기존과 동일하게 GitHub Actions 배포 전 단계에 남겨 두었으며, 두 브라우저 스위트 중 하나라도 실패하면 게시하지 않는다.

## 자체 검토에서 수정한 사항
- 이미 다른 계열을 각성한 플레이어가 시험 중 새 계열의 오의를 쓸 수 있던 조건을 수정.
- 임시 시험 실패에 일반 던전의 금화 페널티가 적용되던 동작을 수정.
- 모바일 가로 화면 회복약 터치 영역 최소 높이 32px 적용.
- 새 서버 모듈 allowlist 누락을 HTTP 테스트로 발견하고 수정.
- 오의와 지역 진입 배너가 동시에 뜨던 겹침 수정; 이동 시 이전 지역 토스트 제거.
- 공격 자세와 hitstop이 확실히 종료되는 수명 검증.

## 결정과 남은 검증
기획부터 개발·main 반영까지 사용자가 위임했으므로 추가 승인 대기 없이 inline 실행했다. 독립 서브에이전트가 없어 코드 검토는 작성자의 자체 검토다.
새 직업을 서버 전체 유일 소유권으로 만들지 않았다. 각자의 싱글플레이 이야기 안에서 얻는 고유 계열이며, 절차는 공개 가능한 규칙이다.
처음 구현은 계열당 2액티브+1오의로 제한했다. 세부 스킬 트리의 추가 진화와 생성형 무한 스토리는 이번 구현이 아니다.
검증된 공통 무공은 그대로 보존했다. 초기 수치 테스트는 공략 가능성과 제약 검증이며, 세 계열의 완벽한 성능 동등함을 입증하지 않는다.
실제 저사양 Android / iPhone Safari 장기 플레이·배터리·프레임 성능은 미검증. 자동 품질 저하는 비필수 그림만 줄이며 전투 규칙은 변경하지 않는다. 고급 적 길찾기·배경음악·음성은 이번 범위 밖이다.

### 실기기 성능 확인용 진단 화면
배포 URL 뒤에 `?perf=1`을 붙여 게임을 시작하면 우측 상단에 성능 HUD가 나타난다. 다른 URL에서는 생성되지 않는다. 평균은 진단 모드에서 게임이 실행되는 동안의 프레임 간격, 최근은 최대 120개 실행 프레임의 평균이다. 느린 프레임 누적은 35ms 초과 횟수이며, `pressure`는 기존 자동 품질 저하 판단에 쓰는 가감 카운터다. `autoLow`는 자동 전환 여부, `quality`는 현재 실제 렌더 품질(0~2), `base`는 기기 기본 설정이다. viewport와 canvas 크기는 CSS 픽셀, DPR은 렌더러에 적용된 값(최대 2)이다.

Android 저사양 기기와 iPhone Safari 각각에서 충전기를 분리하고 OS의 배터리 잔량을 기록한 뒤, 같은 밝기와 조건으로 15분 이상 실제 이동·전투를 반복하며 HUD의 평균/최근 ms, 느린 프레임 누적, autoLow 전환 여부와 발열 체감을 기록한다. HUD는 배터리 소모량을 측정하지 않으므로 전후 배터리 잔량은 기기에서 별도로 확인한다. 화면을 잠그거나 다른 앱으로 이동한 시간은 프레임 측정에서 제외된다. 진단 값은 메모리 안에서만 유지되며 전송, 저장, 플레이 내용 기록은 하지 않는다. 이 절차는 아직 실기기에서 실행하지 않았다.
