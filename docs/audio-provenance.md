# 전투 합성음 제작·연결 기록

제작일: 2026-10-02. 명세: SSANGGYE_IMPROVEMENT_SPEC_v1.1.md 27–28장.

## 자산 목록과 사용 근거

모든 전투음의 원본과 편집본은 저장소 `combat-audio.js`의 `sounds` 표 및 합성 함수다. 이 프로젝트 변경에서 Codex가 작성한 Web Audio oscillator + gain envelope 절차 생성음이며 외부 음원·녹음·샘플·루프·다운로드·제3자 저작물은 사용하지 않는다. 별도 음원 파일이나 BGM을 추가하지 않는다. 사용 근거는 프로젝트를 위한 자체 제작 소스이며 외부 음원 라이선스를 주장하지 않는다.

| 원본/편집본 키 | 제작 방식 | 용도 | 반복 |
| --- | --- | --- | --- |
| swing, hit, heavy | 짧은 하강음, 4개 피치 변주 | 시전 / 실제 피해 / 약점 적중 | 루프 없음 |
| skill, move | 계열별 주파수 모티프, 짧은 이동음 | 성립한 기술 / 실제 이동 | 루프 없음 |
| telegraph, launch | 상승 예고음 / 별도 하강 발사음 | 예고 시작 / 공격 실행 | 루프 없음 |
| hurt, block, absorb | 낮은 충격 / 높은 충돌 / 응축 | 적용된 피해 / 받아내기 / 흡수 | 루프 없음 |
| evade, counter, pursuit, suppress | 짧은 고음 / 저음 / 중음 끊김 | 실제 회피·반격·추격·억제 결과 | 루프 없음 |
| kill, link, attain | 낮은 종결 / 짧은 공명 | 실제 처치·연계·최초 체득 | 루프 없음 |
| ui | 짧은 고음 | UI 전용 채널 | 루프 없음 |

무림은 sine, 현실은 triangle 파형에 짧은 감쇠와 1.13배 주파수를 사용한다. 위험 예고는 두 세계 모두 명확한 sine 상승음이며 세계별 길이·주파수는 구분한다. 기술 계열은 파문 저음, 잔영 고음, 봉인 중음 모티프를 공유한다. 같은 종류 변주는 4개를 순환해 연속 동일 변주를 피한다. 볼륨은 성장과 무관하고 밀도 있는 종결음은 실제 성공에만 발생한다.

## 런타임 정책

- 최초 사용자 조작으로 unlock을 요청한다. suspended/blocked/closed context는 재생을 보류하고 과거 소리를 쌓지 않는다. 실패는 호출자에게 false로 반환하며 게임 상태를 수정하지 않는다.
- 총 24개 oscillator voice, 일반 음성은 20개까지. 예고(4), 피해·방어·흡수·발사(3), 주요 기술·성공(2), 반복 타격(1), UI(0) 순으로 우선한다. 중요 신호는 더 낮은 우선순위 voice를 중단할 수 있다.
- voice당 최대 gain .035, 6ms attack, 지수 감쇠, 최대 0.415초. 이 값은 정적 최대 합산 headroom을 확보하는 초기값이며 실제 청취 검수를 대체하지 않는다.
- session+castId+hit+target+result+kind로 중복을 제한한다. 성공 종류는 0.3초 내 묶지만 예고·피해는 묶지 않는다. preview는 별도 ID이며 전투·보상 사건을 만들지 않는다.
- 저장 키 `ssanggye.audio.v1`은 전체/배경음/전투/UI/음소거를 독립 저장한다. 저장 실패는 게임을 중단하지 않는다. 첫 실행 무음 피드백을 반영하여 신규 기본은 muted=false이며 첫 사용자 입력에서 AudioContext를 해제한다. 사용자가 저장한 음소거 설정은 유지한다. 배경음 트랙은 없지만 설정값은 보존한다.
- `clear()`는 예약한 oscillator stop을 포함한 모든 voice를 즉시 중단한다. 엔진에는 타이머/루프/지연 재생 큐가 없다. 미리듣기가 unlock을 기다리던 중 clear되면 재생하지 않는다. 중복 ID는 clear 이후에도 유지해 같은 사건 재전송을 방지한다.

## 연결

최종 Game 클래스에 `CombatEvents.install(Game,{worldOf})`를 한 번 적용한다. 확정된 act 반환값, HP 변화, 실제 이동, 적 prepare/impact, onRealityEffect와 onDualLink를 관측한다. 기본 헛침은 swing만, 적중은 hit, 처치는 kill을 요청한다. 거부된 행동은 조용하다. 지연 타격은 기존 pending 객체에 일시적 audioCastId를 붙이며 저장/피해/보상은 변경하지 않는다.

app은 `combat-sound`를 `audio.play`에 전달하며 예전 `sound` 전투음을 중복 재생하지 않는다. `audio-clear`, 팝업/일시정지, 전환, 재도전, 저장 로드에 clear한다. 최초 체득은 act/onDualLink/step에서 false→true를 관측해 게임 인스턴스당 한 번 요청하고 중첩 호출에서도 중복하지 않는다. 소리 UI는 미리듣기와 설정만 조작한다. UI 채널 사용 시 `kind:'ui'`를 전달한다.

## 검증과 남은 관문

`node --test tests/combat-audio*.test.cjs`: 초기 누락 모듈 실패 확인 후 10개 통과. gesture 차단, context 생성/재개 실패, 저장/음소거/채널 보존, 시전·대상·타격 중복, 4개 변주, 20+4 중요 신호 공간, 과다 신호 우선순위, 중단, 성공 묶기/예고 보존, preview 격리, 실제 runtime의 흡수·억제·지연 명중을 확인한다.

실제 사람의 음색 품질·장시간 피로도·왜곡 평가는 아직 하지 않았다. 실물 휴대폰·데스크톱·이어폰·내장 스피커별 10분 이상 청취(A-04)는 미검증이다. 보스/다수 적 중요 예고 보존은 자동 cap 검증까지이며 실기기 음향 관문 A-02 완료를 주장하지 않는다. UI 및 게임 전체 실행 검증은 통합 작업의 별도 기록을 따른다.
