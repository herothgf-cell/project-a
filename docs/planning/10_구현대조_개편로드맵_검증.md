## 1. 비교 기준과 확인 범위

비교 저장소는 **herothgf-cell/project-a**다. 이전 Unity RuleWorld와 구분한다. v1.1 작성 때 확인한 게임 기준 커밋은 `91c6262b8478ff8c590a0404fe812fe1f61d2dce`다. v1.2 상세화 직전 main은 `4f41a787386c65f779faa5d36a7b2cefb9a90d34`로, 두 커밋의 차이는 기획 Markdown 17개이며 게임 코드는 같다. 메시지는 `Simplify growth with permanent stats and skill trees`, 시각은 2026-10-07 20:35:29 KST, README의 최신 변경 표기는 v0.12.9다. [SRC-G01/G02]

이후 문서 전용 커밋으로 main SHA가 바뀌어도 게임 구현 비교 기준은 위 커밋으로 고정한다. 새 기획 버전1.2과 게임 v0.12.9를 같은 버전으로 혼용하지 않는다.

검토 범위는 main 메타데이터, README, 첫 성장 안내, advancement.js의 핵심 정의, 최신 변경 일부, skills-tree.browser.cjs, 선행 2026-10-06 문서 2개다. 전체 소스·모든 화면·전체 테스트·배포판을 감사한 것이 아니다. 이번에 게임 테스트는 실행하지 않았으며 과거 문서의 통과 개수를 이번 결과로 인용하지 않는다.

구현 상태는 ‘코드 근거 / 문서 근거 / 구자료 근거 / 확장 필요 / 추가 확인’으로 구분한다. 개선 필요는 구현 유무와 별도다. 기획을 승인받았다고 구현 완료로 바꾸지 않는다.

## 3. 주요 변경 지점

**GAP-01 — 기본 성장의 기연 소유 강제.** D-007에서 분리가 승인됐다. 이제 같은 승인을 다시 기다릴 항목이 아니라 일반 수련·실전 대응으로 본편·경지가 가능한지 설계·구현할 대상이다. 후속 장의 숨은 소유 조건까지 찾아야 한다.

**GAP-02 — 이미 있는 트리의 중복 제작.** 현재 트리의 실제 선행 모델을 활용한다. 계보·성취·수련·저장 이행이 확장 대상이다. D-012의 성장 공식은 테스트 전 최종 확정하지 않는다.

**GAP-03 — 화경 상한.** 이름 배열만 늘리지 않는다. 조건·시련·효과·포인트·메뉴 최대 처리·저장 유효 범위와 설명이 함께 필요하다. D-015에 따라 10장 완료를 최고 단계로 묶지 않는다.

**GAP-04 — 퀘스트 보상처럼 느껴지는 기연.** 발견·시험·체득·명명을 분리한다. [유일] 배지 하나를 붙였다는 이유만으로 발견감 검증을 끝내지 않는다.

**GAP-05 — 세계 정체성.** 현대 판타지의 마력·성력·유물·악마·괴물과 무림의 문파·검로·심법을 구분한다. 과한 SF의 자동 예외를 남기지 않는다. 기존 역할 ID·저장은 표시/아트 변경과 별도로 다룬다.

**GAP-06 — 구문서 UI의 재유입.** 관찰 수첩·해석 장착·무료 스탯 재분배를 오래된 문서에서 가져와 복원하지 않는다. 과거 동작은 역사 기록이지 목표 규칙이 아니다.

**GAP-07 — 스킬 초기화 정책 변경.** 기존 ‘스킬 초기화 가능’은 D-016으로 대체됐다. 목표 UI의 초기화 버튼뿐 아니라 실제 감소·환불·재분배 경로와 관련 테스트도 변경해야 한다. 정식 저장을 바꾸지 않는 연습·초안 취소는 구분한다.

## 5. 단계별 개편 순서

**P0 — 결정 반영과 기준선.** 이번 승인 사항을 문서에 반영한다. 코드 착수 전 최신 게임판·세이브 샘플·현재 테스트를 다시 확인한다. D-003과 D-018~020을 현재 싱글 검증의 선행 승인 항목으로 잡지 않는다.

**P1 — 일반/기연 첫 경험.** 2장 뒤 철수→일반 수련 또는 기연 발견→핵심 행동 하나→현실 재도전→역할 변화. 화산 1계열과 파문 중심 기연 1개를 비교한다. 기연이 없는 저장도 실제로 진행되는지 우선 확인한다.

**P2 — 영구 성장 방식의 실험.** 포인트형·수련형·복합형을 분리된 실험 상태로 비교한다. 초기화 금지는 확정된 정책으로 적용하되 구체 성수·요구량·기존 저장 환산은 D-012 테스트 후 확정한다. 실험 결과가 나오기 전에 정식 세이브를 일괄 변환하지 않는다.

**P3 — 세계·UI·후반 사건.** 현대 퓨전 판타지 표현, 문파 전수 관계, 5~10장 일반/기연 해법을 맞춘다. 소량 아트 비교와 UI를 먼저 검증하고 대량 제작은 보류한다. 화경/S의 설정과 실제 10장 성장 속도를 분리한다.

**P4 — 선택한 후속 시스템.** 필요해진 시점에 마기·성력, 혼합 기연, 협동·공유 서버를 각각 검토한다. 한꺼번에 묶어 개발하지 않는다. 유일 보상 거래·시즌·서버 통합·PvP는 승인된 범위만 구현한다.

이 순서는 개발 제안이며 이번 요청 자체는 문서의 GitHub 등록·갱신이다. 게임 코드 개발을 이미 시작했다는 뜻이 아니다.

## 6. 일반 RPG 기반의 최소 범위

기본 전투·일반 트리·수련·보급·성장 목표가 필요하다. 일반 장비를 최초 검증에 반드시 포함할지는 D-014의 세부 범위로 남아 있다. 포함한다면 최소 슬롯·획득·교체·효과를 먼저 정의한다.

강화석·확률 강화·가챠·길드 경영·거대한 제작 트리·일일 과제를 이번 기연 개편에 자동 추가하지 않는다. 기존 회복약·금화·일반 성장과 한 계열의 완성도를 먼저 확인하는 안이다.

빠른 회귀는 핵심 상태·중복·선행·투자 검사를, 구간 회귀는 장별 실제 진행·보고·세이브를 담당하도록 분리한다. 새 정책을 검증하는 테스트와 과거 정책을 보존하는 테스트가 충돌하면 요구 변경 근거를 기록한다.

## 8. 체감 테스트

정답을 알려주지 않은 참가자에게 초반과 대표 수련을 진행시킨다. ‘어디서 무엇을 발견했는가’, ‘무슨 행동이 강해졌는가’, ‘기연을 못 얻었으면 무엇을 했겠는가’, ‘현실의 역할은 어떻게 달라졌는가’, ‘투자는 되돌릴 수 있는가’를 묻는다.

관찰 지표는 발견 원인 설명, 유효한 기술 사용, 일반 경로 완주, 다음 목표 이해, UI 왕복·혼동, 기연 전후의 상대적인 효율이다. 첫 소규모 실험에서 임의 합격률·확정 배수를 먼저 정하지 않는다. 시연 획득률을 실제 MMO 획득 확률로 보고하지 않는다.

## 9. 문서 배포·관리 검증

GitHub의 `docs/planning/`에 중앙과 상세 문서가 함께 존재해야 한다. 중앙에서 연결한 실제 파일명과 경로를 확인한다. 파일명·문서 ID는 유지하고 결정대장→관련 문서→중앙→변경 이력을 함께 갱신한다.

문서 커밋은 이 폴더의 Markdown만 대상으로 한다. `[skip ci]`를 사용해 기존 push 기반 게임 테스트·배포를 불필요하게 실행하지 않는 방식으로 등록한다. 워크플로 파일은 수정하지 않는다. 실제 등록과 링크 확인 결과는 작업 완료 시 별도로 확인하며, 이 설명 자체가 완료 증거는 아니다.
