# 30. 양세계 첫 성장 순환 실행 계획

2026-10-12 · 사용자 승인: main 직접 개발·검증·푸시·Pages 배포

목표: DOC-29의 확대 범위를 일반 화면에서 이어 플레이할 수 있도록 구현한다. 기획 수치는 초기 검증값이며 목표 플레이 시간은 보장값이 아니다.

## 저장 이행 계약

- 사용자 확인: 기존 1~2장은 유지하고 첫 귀환 후 안정화부터 완료 기반 성장으로 전환한다.
- 기존 명중 기록을 완료 횟수로 환산하지 않는다. 원본 기록·학습·투자·보상을 유지하며 새 완료 횟수와 기존 효과 하한을 함께 사용한다.
- 새 원장은 별도 버전으로 저장한다. 회차 번호, 완료 구간의 유효 사용 기술, 현재 구간, 최초 성취와 반복 정산 횟수를 구분한다.
- 현재 구간은 재접속/실패 시 재시작한다. 완료 구간 기록은 보존하며 최종 성공만 숙련·재료·경험치를 지급한다. 철수는 미정산 회차를 버린다.
- 기존 기본기 각인은 같은 출처로 취급한다. 새 첫 성취를 이유로 중복 각인을 지급하지 않는다. 재료 잔액은 기존 투자와 새 학습·강화를 모두 차감한다.
- 거절 장면은 과거 기록으로 남기며 귀환 후 별도 재수락 사실을 저장한다.

## 구현 순서와 파일 경계

1. `dual-progression.js`, `tests/dual-progression.test.cjs`: 완료 원장·정산·학습·강화·이행 검증. 실패/중복/교체/재접속 사례부터 실패 테스트 작성.
2. `dual-activities.js`: 기존 Game에 활동 경로를 연결. 노방 수련·삼재 기초 과제·토벌 2구성, 안전 거점 왕복과 재전수 구현.
3. 같은 활동 모듈: 현실 공용 슬롯 G1/G2/R1, R1 수련, 기본 레이드·2조건, 보스 전조·지지체·빈틈·체크포인트 구현.
4. `dual-activities-ui.js`, `app.js`, `index.html`: 활동 선택·진행 조건·편성·비용·결과·다음 목표를 기존 대화창/키보드/모바일에 연결.
5. `save-v10.js`, `world-game.js`, `ordinary-growth.js`, `murim-growth.js`, `boundary-resonance.js`: 새 원장의 저장·효과·재료를 기존 시스템과 연결. 이전 여정/보관판 회귀 검사.
6. 자동 검사·브라우저 조작·전체 변경 리뷰 후 원격 main 통합, 재검증, 정확한 변경 파일만 커밋/푸시. 해당 SHA의 Pages 성공 확인.

## 완료/검증 기준

- 이전 저장 재열기, 기존 단계/투자 보존, 손상 원장 거부, 이중 정산/이중 소비 방지.
- 조기 수락과 거절 후 재수락 모두 R1 조건·재료를 확보할 수 있음.
- 실제 적중한 기술만 완료 시 +1. 수련은 지정 기술 하나, 반복 전투는 사용한 기술 모두. 실패한 구간은 제외.
- 기본 레이드 전에는 변이 진입 불가. 첫 완료 보너스는 전체 1회, 두 조건의 반복 보상은 동일.
- G1/G2만으로 세 레이드 조건 완주 가능. R1은 지연 범위 공격, G2는 연속 적중 보상, G1은 즉시 대응.
- 스킬별 강화 조건/잔액/공용 슬롯/회복 재시작값이 화면 설명과 일치.
- `npm test`, 변경 JS 구문 검사, 신규 브라우저 흐름과 기존 무림 귀환 브라우저 검사.
- 저장 실패 시 거래 취소와 사용자 안내. 데스크톱·모바일 화면 확인.

## 리뷰 초점과 후속

저장 신뢰 경계, 과거 보상과 새 재화의 이중 계산, 전투 중 교체/정산 우회, 기존 세계별 성장 누출을 우선 리뷰한다. R2/R3·랭킹·장비는 이번 구현에 포함하지 않는다. 실제 플레이 시간과 반복의 재미는 배포 후 별도 관찰로 검증한다.

진행: 완료 원장 → 활동/전투 → UI/저장 → 회귀 검증 → 독립 리뷰와 수정까지 완료. 실제 검증·제한은 [DOC-31](31_양세계성장_구현과검증.md)에 기록했다. 원격 main 통합 후 동일 변경의 최종 검증·커밋·푸시·배포 확인을 진행한다.
