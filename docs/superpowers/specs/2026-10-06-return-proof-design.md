## 1. 목표와 단계

무림에서 익힌 원리로 현실의 같은 위협을 다르게 해결하고, 직접 보고한 성과가 다음 현장의 결정권으로 이어지는 선택 체험을 만든다. 사용자 문서의 P0~P5가 이번 구현 범위다. 대표 계열은 파문이며 E0/E1→기존 E2 계승→E3 귀환·장착→E4→E5 보고·선택→E6를 연결한다.

잔영·봉인의 기존 기술은 보존하고 공통 임무에서 사용 가능해야 한다. 기존 실제 효과가 새 임무에서 안전하게 기록되는지 회귀 검사하되, 계열별 신규 체득 연출·맞춤 난도·후속 장 개편(P6)은 사람 테스트 결과 전까지 확장하지 않는다. H1~H5, 20~30분 목표, 재미 및 사업성은 자동 테스트로 통과 처리하지 않는다.

새 성장 재화·스킬 레벨·호감도·동행 AI·온라인 분석 서버를 추가하지 않는다. 본편의 도입, 1~10장, 경계의 심장 진입 조건, 기연 소유권, 무료 재수련, 7장 준비 선택을 유지한다. 신규 선택 체험을 하지 않고도 본편을 진행할 수 있어야 한다.

## 3. 구현 방식 선택

1. **권장: 전용 임무 컨트롤러와 좁은 기존 훅.** 별도 모드가 상태·프로필·무보상·복원을 소유한다. 기존 입구, 전투, 보고, 저장은 검증 가능한 함수로 연결한다. 변경 접점은 여러 개지만 본편과의 경계를 검사하기 쉽다.
2. 기존 `comparison` 확장: 코드량은 줄지만 기존 비교 체험의 정착 정책과 새로운 E1/E4 표본·직접 보고 의미가 섞인다.
3. 별도 테스트 전용 미니게임: 본편 위험은 낮지만 실제 계승·귀환·보고 접합을 검증하지 못한다.

1안을 기준으로 계획한다. 신규 의존성이나 전투 엔진 교체는 없다. 저장소의 UMD 모듈 형태를 유지한다.

## 4. 전용 임무와 시간

`return-proof.js`가 상태 전이를 소유한다. 내부 지역 ID `returnProof`는 rift의 배경·충돌 데이터를 재사용하는 런타임 임무다. 일반 rift의 처치 수·클리어·보스 보고를 실행하지 않으며 새 포털을 만들지 않는다.

입구 노출은 `progress >= 12 && fate.stage >= 1`로 한다. 항만 제압만 한 상태와 서린의 2장 최종 보고를 마친 상태를 구분한다. 현실 통합 입구에서 선택하며 기존 본편 목적지를 우선 표시한다.

| 모드 | 진입 | 완료 | 확정되는 결과 |
| --- | --- | --- | --- |
| `baseline` (E1) | 2장 보고 후 | 모든 전용 적 제압 → 회수 지점 2초 → 상호작용 | `baselineCompleted` |
| `proof` (E4) | E1 완료, 계승의 현실 귀환 성취 있음 | 같은 현장·같은 회수 조건 | `proofCompleted`; 실제 유효 효과가 별도 있을 때 `verifiedFamily` |
| `application` (E6) | 직접 보고·역할 선택 후 | 선택 적용 현장의 같은 목표 | `applicationCompleted` |

E4의 미장착은 안내하고 플레이어가 연습 진입을 선택할 수 있게 한다. 기본 공격으로 이긴 경우 임무 성공을 기록하고 기술 증명은 미완료로 남긴다. 이미 강한 저장을 약화하지 않으며 E1 표본 적격성은 별도 로그에 남긴다.

`profileVersion:1`의 압박·강타·측면 사격 3역할을 고정한다. 초기 수치·좌표는 하나의 프로필에 두고 E1/E4를 동일 생성기로 만든다. 강타 예고 1.2초, 후딜 0.8초를 출발점으로 검증한다. 첫 강타와 첫 사격 예고를 겹치지 않게 한다. 새로운 적 추가, 강제 손상, 자동 처치로 성과를 취소하지 않는다.

E1/E4의 시작 HP·MP는 각각 현재 최대치의 100%로 맞추며 실제 성장 수치는 유지한다. 무한 자원은 제공하지 않는다. 시도 종료·실패·후퇴는 입장 전 HP·MP·소모품·쿨다운·기세를 복구한다. 정책을 입장 상세에 표시한다. 임무 처치의 금화·XP·숙련은 0이다.

모든 임무 타이머는 `Game.step` 전후의 `playTime` 차이로 진행한다. 메뉴·대화로 스텝이 멈추거나 타격 정지가 적용되면 예고, 강화 만료, 쿨다운, 확보 타이머가 같이 멈춘다. 별도 wall-clock 타이머로 전투 판정을 하지 않는다.

## 5. 실제 효과, 강화, 안내

`RealitySkills`에 읽기 전용 `readiness(g, action)`을 추가한다. 반환값은 장착·쿨·자원에 따른 `canUse`, `reason`, `boostRemaining`, `charged`, `hasTarget`을 구분한다. 읽기는 런타임 생성·강화 소비·영구 상태 변경을 하지 않는다. 쿨·자원 때문에 사용할 수 없다는 것과 지금 유효 대상이 없다는 것도 별개다.

기존 강화 소비를 `consumeBoost(g, consumer)`로 모아 수동 기본 공격·후속기·만료가 같은 상태를 참조하게 한다. 기본 타격 소비 뒤 후속기 UI에 강화가 남지 않아야 한다. 비용·쿨을 몰래 초기화하지 않는다.

실제 효과 이벤트는 `castId/targetId/kind`로 중복 제거한다. 활성 E4의 전용 대상, 해당 실행 인스턴스, 수동 입력에서 발생한 `ripple:absorb`, `echo:evade`, `seal:suppress`만 새 검증 근거로 받는다. E1, E2, 일반 전장, 6장 잔류 파형·7장·10장 효과는 새 검증 근거가 아니다. 평가·심화·발현·무림 숙련으로 새 훅이 누출되지 않도록 대상과 모드 조건을 명시한다.

유효 E4 효과는 기존 현실 기술의 `settled` 전이를 명시적으로 허용하되 숙련·XP를 주지 않는다. 이 사건 자체는 저장 가능한 확정 증거다. 임무 완료와 직접 보고는 이후 별도 조건이다. 강화와 경직 등 일시 효과는 저장된 영구 증거와 분리한다.

실제 대응 성공의 타격 정지는 초기 0.06초로 두고 같은 사건의 연타에 중복 적용하지 않는다. 저효과 설정에서는 줄이거나 생략한다. 무효 흡수 창은 `대기 종료`로 표현하고 피격·시점 근거 없이 `늦음`이라고 단정하지 않는다. 예고/발동/후딜은 색과 함께 형태·문구로 구분한다.

E2는 기존 비경의 빌린 기술과 계승 경로를 유지한다. 파문 관찰→받아내기→후속 활용→거리 응용 안내는 선택 연습이며, 기존 `fate.proven`·계승의 새 필수 조건이 아니다. 실제 성공 사건을 설명하고 실패 2회 이후 선택 도움말을 제공한다. 자동 성공·무적·강제 정답은 없다. 이미 얻은 기술을 숨기거나 잠그지 않는다.

E3 변화 카드는 `WorldAchievements`가 만든 정착 결과를 읽는다. 주 정보는 현실의 `충격 흡수 / 압축 반격`, 적용 세계, 장착 행동이다. 능력치와 출처는 접힌 상세로 제공한다. 카드 열기·닫기는 보상이나 실전 증명을 만들지 않는다.

## 6. 직접 보고와 역할 선택

`reported`는 E4 완료와 검증된 계열이 있고 현실 기지의 서린에게 직접 보고한 경우에만 켠다. 임무만 성공한 경우 전투 성과 대사와 재연습 안내만 제공한다. 새 역할을 아는 대사와 선택권은 보고 전에 나타나지 않는다.

`WorldReports`의 동일 역할 이력·보고·보급 원장을 사용한다. 이미 초동 대응자이면 새 승격처럼 공지하거나 회복약을 다시 지급하지 않는다. 최대 보유량 99 때문에 지급하지 못한 보급은 기존 정책을 유지한다. 공식 등급과 7장 준비 선택은 변경하지 않는다.

선택 미리보기는 상태를 바꾸지 않는다. 확정 후 E6 시작 시 런타임에 선택을 복사하여 도중에 바꾸지 못하게 한다. 시도가 끝난 뒤 거점에서는 다른 선택을 재체험할 수 있다. 영구적인 최초 보고와 완료 기록은 지우지 않는다.

- `cut-support`: 사격 위협 1개 비활성, 안전 영역 없음.
- `secure-route`: 사격 위협 유지, 표시된 영역 안에서 받는 피해 배율 0.75. 무적 아님.

도겸은 고정 후방 표시·대사로 회수 역할을 나타낸다. 이동/전투 AI를 추가하지 않는다. 종료 시 선택과 실제 현장 변화 한 줄을 회수한다.

## 7. 저장과 실패의 계약

`worldState.returnProof` 하위 스키마 버전은 1. 필드는 문서의 `baselineCompleted`, `proofCompleted`, `verifiedFamily`, `reported`, `roleChoice`, `applicationCompleted`를 사용하고 최소 E4 근거(`family`, `profileVersion`, `encounterId`, `castId`, `targetId`, `kind`)를 함께 검증한다. 기연 소유·귀환 성취 없는 계열과 선행 없는 보고/선택/완료를 거부한다.

최상위 save-v10과 improvementVersion 2를 유지하고 새 묶음이 없는 기존 저장만 초기 미체험 상태로 이행한다. 존재하지만 손상된 새 묶음을 성공 상태로 보정하지 않는다. 후기 저장에 E1·E4·보고를 가짜 생성하지 않는다.

`proofRuntime`은 스냅샷, 적, 타이머, 이벤트 중복 집합, 적용 선택을 가진 일시 객체다. Set/Map을 보존하는 복제를 사용한다. 중간 저장은 입장 전 본편 상태와 확정된 영구 증거를 직렬화하고, 최상위 선택 필드 `returnProofSession`에 버전·모드·프로필·적용 선택만 저장한다. 적 HP, 강화, 진행 중 확보 시간은 저장하지 않는다.

불러오기는 본편 스냅샷을 먼저 검증한 후 유효한 진행 세션을 같은 모드 시작점으로 복원한다. 저장 투영은 `try/finally`로 실제 플레이 상태를 원상 복구한다. 저장 실패, 중복 클릭, 가져오기 실패는 원본 저장·실행 중 상태를 보호한다. 보고·선택 같은 확정 UI는 기존 저장 트랜잭션과 결합하고 실패를 저장 성공으로 알리지 않는다.

## 8. 검증과 관찰

기능 F01~F28, 전투 CB01~CB08을 테스트와 수동 확인 항목으로 연결한다. 기존 670개 테스트는 기준이며 신규 기능 후에 다시 실행한다. 모바일 360×640, 가로 844×390, 200% 확대, 재지정 키, 대화 닫기 입력 누출과 비동기 입장 취소를 포함한다.

로컬 테스트 로그는 기본 꺼짐이고 제품 보상 판정의 입력이 아니다. opt-in 개발 화면에서 사건 단위로 수집·내보내며 외부 전송하지 않는다. 로그를 끄거나 로그 저장이 실패해도 게임 규칙은 같아야 한다. 익명 세션·빌드·기기·프로필·행동·실제 효과·도움 개입을 분리한다. 원본 게임 저장을 공유 자료로 자동 첨부하지 않는다.

2장 보고 후 테스트 시작점을 `SaveSlots.keys.test`에만 추가한다. 기연을 미리 주지 않고 본편 1~2장 경험을 생략했다는 한계를 기록한다. 실사용자 8명 탐색 테스트와 동일 스탯 A/B 피드백 비교의 기록 양식을 제공하되 결과는 실제 시행 전까지 `미실행`이다.

## 9. 완료 판정

기능 구현 완료는 코드 검사·기능 테스트·현재 버전 및 신규 브라우저 테스트·프로토타입 빌드가 통과하고 저장/보상/본편 교착/입력 누출/허위 효과 판정 결함이 없을 때만 표시한다. 자동 플레이로 사람의 성장·인정·재미 판단을 대체하지 않는다. 이번 요청은 새 브랜치 작업이며 원격 push·Pages 배포는 별도 요청 사항이다.
