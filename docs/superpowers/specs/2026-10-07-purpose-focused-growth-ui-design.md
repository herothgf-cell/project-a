# 쌍계 · 목적별 성장 UI/UX 시안

2026-10-07 · 검토용 제안 · 기준 v0.12.5 / 3f66f38. 게임 구현·배포에 적용하지 않은 시안이다.

## 1. 설계 기준

사용자가 화면을 열기 전에 할 일을 예측할 수 있어야 한다. 캐릭터는 스탯을 확인하고 올리는 곳, 무공/스킬은 기술을 확인하고 강화하는 곳, 경지 돌파와 헌터 승급은 다음 자격에 도전하는 곳이다. 같은 기능의 실행 화면은 한 곳만 둔다.

현재 문제는 화면 크기보다 기능의 배치다. character-ui.js는 스탯 조회 후 다른 화면으로 이동하게 하고, development-ui.js와 resonance-ui.js는 기술 조회·장착·강화를 나눈다. growth-screen.js에는 심법·경지·승급이 함께 있다. 공명 획득은 귀환 안내와 보관함을 찾아봐야 알 수 있다.

추천안은 최상단 직접 진입 4개다. '성장' 아래 탭을 추가하는 안은 기존 탐색 문제를 유지하고, 모든 기능을 한 화면에 모으는 안은 목적을 다시 섞으므로 채택하지 않는다.

## 2. 최상단 메뉴

`캐릭터 [결정 8] | 무공/스킬 [각인 3] | 경지 돌파 [잠김] | 헌터 승급 [잠김]`

네 버튼은 화면 상단 같은 위치에 유지한다. 경지와 승급을 더보기·성장 탭 안에 넣지 않는다. 임무·기록·설정은 기존 보조 메뉴로 유지한다. 넓은 화면에서는 한 줄, 360px에서는 2×2로 배치하여 두 승급 버튼이 가려지지 않게 한다.

- 수량 배지: 해당 목적에 사용할 수 있는 실제 잔량. 메뉴를 읽었다고 없어지지 않는다.
- NEW 표식: 아직 확인하지 않은 획득이나 해금. 숫자 배지와 별개다.
- 잠금 버튼도 눌러 다음 이야기 조건을 볼 수 있다. 회색 버튼만 놓거나 숨기지 않는다.
- 해금·미충족·도전 가능·결과 확정 대기를 다른 상태로 취급한다.
- 현재 세계와 조회 세계를 구분한다. 다른 세계의 화면을 봐도 실제 위치·장착이 바뀌지 않는다.

| 메뉴 | 허용하는 주된 작업 | 옮기거나 제거할 내용 |
|---|---|---|
| 캐릭터 | 최종 스탯 조회, 출처 확인, 능력치 배분·환불 | 스킬 트리, 스토리 보고, 도전 목록 |
| 무공/스킬 | 기술별 효과·강화·숙련 확인, 계열/운용 장착 | 스탯 배분, 승급 신청 |
| 경지 돌파 | 무림 경지 조건 확인, 시련 진입, 돌파 확정 | 특화 포인트 배분은 캐릭터로 이동 |
| 헌터 승급 | 현실 평가 조건 확인, 평가 진입, 결과 보고 안내 | 훈련 포인트 배분은 캐릭터로 이동 |

공명 도전과 성장 목표는 임무의 선택 도전 영역으로 옮긴다. '경계공명'은 성장의 출처·아이템 설명으로 남기며 또 하나의 성장 허브로 만들지 않는다. 심법 투자는 무공/스킬의 공통 운용으로 합친다.

## 3. 캐릭터 · 스탯 확인과 배분

### 기본 화면

1. 윤서 / 선택 세계 / 레벨 / 현재 위치. 큰 일러스트보다 숫자와 실행 영역을 먼저 보이게 한다.
2. 현재 최종 스탯: 공격력, 최대 생명, 최대 기력. 현재 HP/MP는 최대치 아래 보조 표기한다.
3. 사용할 성장 자원: 이름, 아이콘, 실제 보유량, 적용 세계, 최근 획득처.
4. 각 스탯 행: 현재 → 적용 후 / 이번 배분 수 / 감소·증가.
5. 하단 확정 영역: 총 소비, 적용 후 잔량, 확정 버튼. 미리보기 수정과 저장을 분리한다.

현실 자원은 공명 결정과 헌터 훈련 포인트, 무림 자원은 경지 특화 포인트다. 자원마다 단위·한도가 다르므로 선택기를 두고 한 번에 한 자원의 배분만 편집한다. 금화·각인까지 하나의 지갑으로 모으지 않는다. 스탯 출처 상세는 기본/레벨, 기존 성취, 공명, 심법, 경지·훈련으로 나눈다.

### 공명 결정 예시

`공명 결정 8개 · 현실 스탯용` / `최근 획득: 첫 기연 영구 계승 +8`

| 항목 | 현재 | 첫 추천 배분 후 | 소비 |
|---|---:|---:|---:|
| 공격 | 16 | 20 | 4개 |
| 최대 생명 | 120 | 144 | 4개 |
| 최대 기력 | 80 | 80 | 0개 |

'첫 정착 추천'은 초안만 채운다. 기본 강조 버튼은 '결정 8개로 배분 확정'. 초안이 없으면 '배분할 스탯을 선택하세요'로 비활성화한다. 적용 성공 후 같은 화면에서 숫자 변화와 '저장됨'을 알린다. 실패하면 잔량·스탯 모두 원복하고 초안은 재시도할 수 있게 남긴다.

### 예외 상태

- 0개: '보유 0개'를 유지하고 실제 다음 미수령 획득처 1개를 표시한다. 이미 받은 최초 보상을 다시 추천하지 않는다.
- 무림에서 현실 조회: '공명 결정은 보관 중입니다. 현실 기지에서 배분할 수 있습니다.' 미리보기는 허용하되 확정은 잠근다.
- 전투 중: 조회·초안만 가능. '현실 기지에서 확정'을 고정 표기한다.
- 한도: '공격 4/4 · 총 투자 8/10'을 따로 표시한다. 공격 한도 때문에 생명·기력까지 비활성화하지 않는다.
- 새 한도: 첫 현장 성과 인정 8/20, 관측소 실전 완료 12/30. 상한은 목표 달성률처럼 강조하지 않는다.
- 환불: 하위 보조 버튼으로 제공한다. 선택한 재원의 새 투자만 환불하며 이전 고정 성취는 보존한다. 확인에는 환불량·줄어드는 최대 스탯·현재 HP/MP 비율 유지가 나온다.
- 변경 중 세계/자원/메뉴 이동: '배분 확정 / 초안 버리기 / 계속 편집'을 보여주며 조용히 초안을 버리지 않는다.

## 4. 무공/스킬 · 목록과 기술 상세

### 화면 구조

상단은 세계 선택과 해당 세계의 스킬 강화 자원만 표시한다. 현실은 무공 각인, 무림은 기존 수련 포인트다. 그 아래 '공통 운용 / 파문 / 잔영 / 봉인'을 둔다. 계열 선택과 실제 장착은 별도 상태이며 선택만으로 장착하지 않는다.

데스크톱은 왼쪽 기술 목록, 오른쪽 선택 기술 상세다. 모바일은 목록에서 기술을 누르면 상세 한 화면으로 이동하고 '기술 목록'으로 돌아간다. 모든 계열의 상세 설명을 세로로 한꺼번에 펼치지 않는다.

기술 목록에는 입력 키, 기술 이름, 강화 Lv., 체득/잠금 상태, 해당 기술의 개별 숙련을 표시한다. 상세에는 실제 현재 효과·최종 기력 비용·재사용 시간, 선택 가능한 강화의 현재→다음 효과, 각인 비용, 적용 위치를 둔다.

### 체득·강화·숙련의 구분

| 정보 | 질문에 대한 답 | 조작 |
|---|---|---|
| 체득 | 이 기술을 사용할 수 있는가? | 이야기/실습으로 해금. 각인 구매로 우회 불가 |
| 강화 Lv. | 이 기술을 어떻게 강화했는가? | 각인을 소비해 운용을 해금·강화 |
| 개별 숙련 | 이 기술을 실전에서 얼마나 유효하게 썼는가? | 유효 행동으로 기록. 각인 소비로 상승하지 않음 |

현재 코드에는 계열 숙련만 있다. 기술별 숙련을 같은 계열 숫자로 복제해 보여주지 않는다. 제안은 세계별·행동별 독립 숙련 기록을 추가하고, 기존 계열 숙련/최대 12% 효과는 그대로 보존하는 것이다. 새 개별 숙련을 추가 피해 보너스로 중복 적용하지 않는다. 기존 저장은 '이전 개별 기록 없음 · 업데이트 이후 측정'으로 시작하며 과거 사용 횟수를 추정하지 않는다. 시안의 개별 숙련 수치는 제안 화면용 예시다.

실제 흡수 성공은 흡수, 예고 회피 성공은 긴급 가속, 유효 억제는 균열 억제에 기록한다. 타격 기술은 적중한 직접 행동을 기록하고, 같은 사용의 다중/지연 타격은 한 번만 센다. 허공·키 반복·대여 시험·보상 없는 비교/도전은 기존 숙련 획득 정책을 따른다. 패시브는 '숙련 대상 아님'으로 표시한다. 확률·숨은 점수로 표현하지 않는다.

### 기존 강화 규칙을 정직하게 표시

- 공통 운용 노드는 기존 2~3랭크와 비용을 유지하고 실제 랭크를 표시한다.
- Q는 기본 Lv.1 → 선택한 운용 적용 시 Lv.2. 안정/절약은 각각 해금하되 활성화는 하나다. 두 번째 방향 구매를 Lv.3이나 효과 합산으로 표시하지 않는다. '다른 운용 해금'으로 안내한다.
- R은 기존 조건인 Q 운용 하나 해금 + R 체득 후 Lv.1 → Lv.2 강화가 가능하다.
- F는 이야기 체득 후 Lv.1이며 현 범위에는 유료 강화가 없다. '추가 강화 없음'을 표시한다.
- 모든 기술에 여러 단계의 새 강화 레벨을 넣으려면 효과·각인 공급·상한을 별도 설계해야 한다. 이번 시안은 기존 경제에서 가능한 강화만 보여준다.

선택한 기술의 '각인 1개로 강화'가 유일한 주 실행 버튼이다. 효과가 배타적이면 구매 후 활성화되는 방향을 사전에 명시한다. 이미 가진 방향은 '이 운용 활성화'로 바뀌고 무료다. 정박+지속 억제는 '실제 6초 유지 · 추가 시간 효과 없음'을 구매 전부터 표시한다. 스킬 초기화는 하위 관리 영역으로 둔다.

R 잠금 문구는 '4장 구조 완료 후 백련의 후속 실습을 마치세요', F는 '7장 위기 실전에서 체득합니다'. 각인 부족, 선행 강화 부족, 이야기 미체득, 안전 거점 아님을 서로 다른 사유로 표시한다.

## 5. 경지 돌파 / 헌터 승급 · 이야기와 해금

두 메뉴 모두 처음부터 상단에 자리를 확보하고 잠금 상태에서는 다음 이야기 조건만 공개한다. 먼 미래 단계의 조건·보상은 접어 둔다. 아래는 현재 코드의 실제 장별 자격을 기준으로 한 제안이다.

| 메뉴 | 첫 해금 제안 | 후속 이야기 자격 |
|---|---|---|
| 경지 돌파 | 3장 결과 보고 완료 | 이류: 3장, 일류: 6장, 절정: 8장, 초절정: 9장 |
| 헌터 승급 | 3장 결과 보고 완료 | D: 3장, C: 5장, B: 7장, A: 8장, S: 9장 |

경지는 이야기 해금 후에도 무림 숙련 합계 8, 기연 계승·증명, 두 세계 실전 조건을 확인한다. 일류는 숙련 합계 16·한 계열 8·6장 심화 체득을 요구한다. '메뉴 해금'이 '모든 조건 충족'을 뜻하지 않는다.

상태 순서: 잠김 → 해금/준비 중 → 도전 가능 → 시련/평가 중 → 결과 확정 대기 → 달성.

- 잠김: '3장 결과를 서린에게 보고하면 해금됩니다' + '현재 임무 안내'. 사용자가 재화를 내면 열릴 것처럼 표시하지 않는다.
- 해금: 상단 자물쇠가 사라지고 NEW가 한 번 표시된다. 강제 창 이동 없이 '경지 시련과 헌터 평가가 열렸습니다'를 안내한다.
- 준비 중: 완료/미완료 조건 각각 표시. 미완료 조건을 누르면 정확한 목적지나 관련 기술로 연결한다.
- 도전 가능: 예상 보상과 성공 조건을 먼저 보여주고 한 버튼으로 진입한다. 해당 세계 안전 거점에서만 실행한다.
- 경지 시련 성공: 청운촌에서 '돌파 확정'. 능력치 보상과 특화 포인트 지급을 저장한 뒤 '캐릭터에서 배분'으로 연결한다.
- 헌터 평가 성공: '서린 보고 대기'. 보고로 등급 확정 후 '캐릭터에서 훈련 포인트 배분'으로 연결한다. 화면 버튼만으로 NPC 보고를 우회하지 않는다.
- 실패/철수: '비용 없이 다시 도전'과 복원 내용을 표시한다. 도전 버튼은 원래 거점에서 바로 재신청 가능하게 한다.

스토리 이벤트, 시련 기록, 실제 실행 가능 여부를 같은 판정으로 계산한다. 새로고침·옛 저장에서 이미 달성한 이야기 조건을 읽어 해금한다. 화면만 열고 닫아야 갱신되는 구조를 피한다. 같은 해금 안내는 완료 이벤트 ID당 한 번이다.

## 6. 성장 아이템 획득을 놓치지 않는 흐름

획득 순간 / 계속 남는 잔량 / 되찾을 수 있는 출처의 세 지점에 표시한다.

1. **획득 순간**: 저장 성공 직후 비차단 알림. '공명 결정 +8 · 보유 0 → 8', '첫 기연 영구 계승', '현실 스탯 배분에 사용'을 함께 보여준다. 각인도 자기 이름과 사용처를 표시한다. 초안 기본 노출 8초이며 전투 중에는 행동을 가리지 않는 위치, 대화 중이면 종료 뒤 표시한다.
2. **상단 목적지**: 캐릭터에는 결정 잔량, 무공/스킬에는 각인 잔량과 NEW. 소비해 0이 돼도 화면 안의 보유량 0은 남긴다. 다른 포인트가 열리면 상세에서 자원별로 구분하며 서로 합산하지 않는다.
3. **사용 화면**: 자원 바로 아래 '최근 획득 +8 · 첫 기연 영구 계승'과 '획득 내역'. 내역은 그 아이템의 출처만 보여주고 별도 보관함으로 이동시키지 않는다.

알림의 '스탯 배분'은 캐릭터의 결정 배분, '스킬 강화'는 무공/스킬의 강화 가능 기술을 연다. 실제 전투 중에는 이동을 실행하지 않고 목적지 안내만 남기며, 기존 전투/메뉴 중단 정책을 따른다. 무림에서는 '획득 완료 · 현실 귀환 후 사용'으로 표시한다. 귀환은 재지급으로 표현하지 않는다.

알림 닫기와 획득 내역 확인은 다르다. 사라진 토스트 때문에 NEW를 지우지 않는다. 내역을 실제로 본 뒤 읽음 처리한다. 보상 ID, 보유, 완료 기록 저장이 모두 성공한 다음 획득 성공을 표시한다. 빠른 클릭·재접속으로 다시 지급하지 않는다.

## 7. 표현·접근성

- 현실은 청색, 무림은 금색의 기존 방향을 유지한다. 금색 결정 출처와 청색 현실 적용을 이름·문양·텍스트로도 구별한다.
- 기존의 큰 장식 헤더를 줄여 자원과 핵심 행동이 첫 화면에 보이게 한다. 설명은 요약 한 줄, 계산 출처는 펼침으로 제공한다.
- 숫자는 현재, 초안, 확정을 구분한다. 색만으로 증가를 표현하지 않고 '+24', '적용 후'를 함께 쓴다.
- 모바일 버튼 터치 영역 44px 이상. 200% 확대에서도 메뉴·자원·확정 버튼이 가로로 잘리지 않게 한다.
- PC에서는 목록+상세, 모바일에서는 목록→상세를 쓴다. 기술 목록으로 돌아올 때 선택·스크롤을 보존한다.
- Tab/Shift+Tab과 Enter/Space로 조작. 증가 후 초점은 같은 버튼에 유지한다. 잠긴 버튼도 잠금 사유를 읽을 수 있다.
- 메뉴 열기·세계 보기·기술 선택·목표 조회만으로 재화를 소비하거나 실제 장착을 바꾸지 않는다.

## 8. 구현 분리와 인수 기준

구현 순서는 ① 네 상단 진입점과 목적별 화면 ② 동일 화면의 스탯/기술 투자 ③ 아이템 영수증·잔량·출처 안내 ④ 이야기 해금 상태 통합 ⑤ 개별 숙련 저장·이전이다. 기존 모델 계산을 재사용하고 UI에 보상·해금 조건을 복사하지 않는다.

통과 조건:

- 캐릭터 진입 후 화면 이동 없이 현재 스탯 확인→결정 배분→변화 확인이 가능하다.
- 무공/스킬에서 기술 선택→개별 숙련 확인→강화→실제 비용 확인이 가능하다.
- 모든 Q 방향을 해금해도 동시에 적용되지 않으며 목록 레벨이 거짓 합산되지 않는다.
- 초기에 잠긴 경지·승급이 이야기 결과 보고 직후 해금된다. 재접속 시 상태와 안내 중복 여부도 일치한다.
- 토스트를 놓쳐도 잔량·NEW·최근 획득처로 아이템을 얻었음을 알 수 있다.
- 0개/타세계/전투 중/한도/저장 실패를 재화 부족 하나로 뭉뚱그리지 않는다.
- 경지·헌터 보상 포인트는 캐릭터에서, 심법은 무공/스킬에서만 배분한다.
- 360px·200% 글자·키보드에서 같은 핵심 작업을 완료한다.
- 기존 저장의 수치·계열 숙련·체득·투자·완료 ID를 보존하고, 없던 개별 숙련 이력은 만들지 않는다.
