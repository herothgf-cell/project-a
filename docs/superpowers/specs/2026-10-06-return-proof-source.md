## 01. 목표·가설·이번 개발 범위

| ID | 검증할 가설 | 관찰할 증거 |
| --- | --- | --- |
| H1 변화 | 플레이어는 무림 방문 전후의 해결 방식 차이를 느낀다 | 이전/이후 행동을 도움 없이 설명 |
| H2 전투 | 대응 성공이 기본 공격 반복보다 즐겁다 | 스스로 Q 활용을 반복하고 R 기회를 사용 |
| H3 인정 | 성과가 타인의 신뢰와 역할로 연결된다고 느낀다 | 맡게 된 판단과 현장 변화를 기억 |
| H4 이해 | 새 성장 메뉴 없이도 능력과 다음 행동을 이해한다 | 정착·장착·실전 증명의 차이를 실제 수행 |
| H5 지속 | 한 번의 경험이 다음 탐구 욕구로 이어진다 | 자발적 재도전·다른 계열 플레이 선택 |

투자 관점의 목적은 이 다섯 가설을 검증할 수 있는 증거를 만드는 것이다. 기능 개수·문서 분량·장 수는 성공 지표로 사용하지 않는다. 소규모 테스트 통과는 재미의 초기 근거이며 시장 수요·매출·사업성 검증은 아니다.

| 포함 | 이번에 제외 |
| --- | --- |
| 기존 지역의 짧은 임무 모드, 전후 비교, 역할 선택 | 신규 대형 지역·11장 이후 확장 |
| 기연 성공·후속 기회 표시, 적 예고·빈틈 조정 | 모든 기술의 수치 전면 개편 |
| 첫 기연 전후 집중 구간, 기존 저장 보호 | 기연을 도입 직후 자동 지급하는 본편 단축 |
| 사용성·기능·전투·재플레이 탐색 | 온라인 분석 서버·과금·랭킹·운영 시스템 |

출시 본편의 도입과 1~2장은 그대로 존중한다. 아래 20~30분은 2장 후 체크포인트에서 시작하는 테스트 세션의 목표이며, 새 게임에서 기연까지 걸리는 실제 시간은 별도로 측정한다. 테스트 편의를 위한 시작 지점이 본편 경험을 증명하지는 않는다.

## 02. 기존 흐름과 접합 — 모순 없이 넣는 방법

권장 삽입 지점은 2장 최종 보고 후~3장 첫 기연 계승 및 현실 증명 사이이다. 이미 균열·항만을 해결한 윤서를 무능한 회수 인력으로 되돌리지 않는다. 서린은 전투 성과를 인정하되 새로운 복합 현장에서 어떤 역할을 맡길지 판단하는 상황을 만든다.

| 기존 요소 | 유지 | 이번 제안 |
| --- | --- | --- |
| 1~2장 승리 | 모든 처치·진행·수련 보존 | 기억을 취소하거나 적을 무적으로 만들지 않음 |
| 3장 기연 | 기존 발견·증명·계승 경로 | 원리별 전투 피드백과 안내 개선 |
| 현실 귀환 | 성취 정착·현실 장착·실전 증명 분리 | 정착 결과를 첫 대응 현장에 연결 |
| 경계의 심장 | 기존 3장 본편과 최종 보고 | 비교 현장을 새 필수 입장 조건으로 넣지 않음 |
| 초동 대응 역할 | 기존 first-response와 보급 원장 | 신규 현장 증거를 동일 역할에 연결; 이중 보상 금지 |
| 7장 준비 선택 | 기존 대피/정예 선택 보존 | 초반 역할 선택을 7장 선택으로 자동 복사하지 않음 |

1차 개발에서는 비교 임무를 선택 체험으로 노출하고 기존 본편 경로를 유지한다. 플레이테스트 후 본편에 더 강하게 통합하려면 길이·이탈·진행 교착을 다시 검증한다. 처음부터 필수 반복 현장을 추가하지 않는다.

이미 성장한 저장

기연을 이미 가진 사람은 체득 전 장면을 정상 능력으로 재방문할 수 있으나 전후 비교 표본에서 제외한다. 능력을 회수하거나 과거에 약했다고 가짜 기록을 만들지 않는다. 이미 초동 대응자인 사람에게 역할 승격·회복약을 다시 지급하지 않고 다른 전술 선택을 체험할 수 있게 한다.

| E2 무림 체득 5~7분 | 백련 해석→무명 비경 원리 증명→기연 계승 | 파문 Q의 의미와 Q→R 활용 |

| E5 인정·판단 2~3분 | 서린에게 직접 보고→다음 진입 우선순위 선택 | 결정권과 전장 변화 |
| E6 적용 전투 3~5분 | 선택 결과가 반영된 짧은 정예전 | 역할 변화의 회수; 재도전/다른 계열 선택 |

합계 목표는19~28분이며 안내·조작 차이를 포함해20~30분으로 관찰한다. 이 시간은 개발 목표다. 대화 자동 스킵이나 강제 이동으로 맞추지 않는다. 테스트용 체크포인트는 본편 저장과 분리한다.

대표 MVP는 파문 1개, 짧은 현장 레이아웃 1개, 위협 프로필 3종, 선택 결과 2개다. 같은 현장 재사용은 전후 비교를 위한 의도이며 세 번째부터는 새 판단이 생겨야 한다. 전체 10장에 같은 비교 구조를 반복하지 않는다.

## 04. E1 체득 전 — 한계보다 미해결 선택을 남긴다

현장명 제안: 잊힌 지하역·회수 통로. 기존 rift 배경을 쓰는 별도 임무 모드이며 일반 rift 클리어 횟수·지역 보상·3장 진행을 직접 변경하지 않는다. 별도 지역 포털 없이 현실 통합 입구에서 선택한다.

| 목표 | 압박 적과 강타 정예를 제압한 뒤 회수 지점에서2초 확보, E로 회수 완료 |

대사 초안

서린: “항만에서 보여준 건 확인했어. 이번에는 통로와 회수 지점을 같이 봐야 해. 우선 현장 구성을 확인해 줘.”도겸: “회수 장비는 내가 맡을게. 강타와 옆 사격이 겹치면 한 번 물러나도 돼.”

플레이어가 쉽게 제압했다면 “전방은 충분히 맡길 수 있겠네. 다른 대응도 확인해 보자”라고 인정한다. 승리 후 일부러 잔해를 떨어뜨리거나 NPC를 다치게 해 성과를 취소하지 않는다. 이 사람에게는 시간 단축보다 적의 통제와 선택 변화가 귀환 보상이 된다.

## 05. E2 무림 체득 — 파문부터 배우는 짧은 연습

| 단계 | 플레이어 행동 | 통과/실패 처리 |
| --- | --- | --- |
| 관찰 | 강타 정예의 같은 예고를 한 번 본다 | 맞을 필요 없음; 예고 발생을 관찰 증거로 기록 |
| 빌린 호흡 | Q 파문세로 실제 공격을 받아낸다 | 실제 방어 사건만 성공. 허공 입력·무적 상태로 넘긴 공격은 구분 |
| 활용 | 파문 축적을 R 역류참으로 소비한다 | 유효 대상 적중으로 후속 활용 확인 |
| 응용 | 거리가 조금 달라진 한 번의 예고에 대응한다 | 동일 입력 연타가 아니라 거리·시점 재판단 |
| 계승 | 기존 소유권 획득 경로로 확정 | 원래 기연 조건·이력 유지. 무료 능력을 별도 복제하지 않음 |

권장 안내 순서: “공격이 닿기 직전에 Q”→성공 시 검의 축적 표시→“쌓인 힘을 R로 돌려보내기”. Q와 R을 이해하기 전 F·진화·경지·심법 트리를 한꺼번에 설명하지 않는다. 다만 이미 보유한 기능을 감추거나 사용 불가로 만들지는 않는다.

실패2회 뒤에는 예고 구간의 차이를 시각적으로 설명하는 선택 도움말을 제공한다. 자동 성공·영구 무적·강제 정답 입력은 제공하지 않는다. 연습을 종료하고 본편으로 돌아갈 수 있어야 하며 신규 응용 단계가 기존 기연 소유권의 추가 필수조건이 되지 않는다.

서사 연결

백련: “힘이 모자라서 물러난 것만은 아닐 게다. 버틸 때와 흘릴 때를 나누어 보아라.”윤서: “그 통로에서도, 한 번만 공격을 받아낼 수 있었다면 움직일 틈이 있었겠습니다.”현실 문제를 백련이 먼저 아는 대사는 금지한다. 윤서의 보고 뒤에만 해석한다.

## 06. E3~E4 귀환 — 같은 위협을 다른 방식으로 해결

변화 카드

제목: “현실에서 쓸 수 있는 새 대응”. 주 정보는 충격 흡수·압축 반격과 적용 세계. HP·공격 보너스는 접힌 상세에서 출처와 함께 확인한다. 카드 자체는 성취를 지급하지 않고 정착 결과를 읽는다. 대표 버튼은 “현실 무공에서 장착”, 보조 버튼은 “나중에”.

기연을 계승한 것, 현실에서 사용 가능해진 것, 장착한 것, 실제 흡수에 성공한 것을 구분한다. 메뉴를 닫았다고 실전 증명 플래그를 켜지 않는다. E4 진입 전 장착 여부를 알리되 다른 본편 진행을 막지 않는다.

| 항목 | 명세 |
| --- | --- |
| 비교 공정성 | E1과 같은 적 역할·HP·피해·배치·예고·동일 시작 자원 비율 |
| 자연 성장 | 실제 무림 방문으로 얻은 레벨·성취는 보존. 시험 편의를 위해 몰래 적을 약화하지 않음 |
| 기술 차이 | 현실 Q는 충격 흡수, R은 압축 반격. 무림 기술명 그대로 안내하지 않음 |
| 목표 | E1과 같은 회수 지점 확보. 기술 성공 여부와 임무 성공은 별도로 기록 |
| 성공 표현 | 실제 흡수→충격 보관 표식→후속 타격 가능 표시→타격/적 반응 |
| 실패 표현 | 흡수 시도 후 실제 공격이 없으면 “대기 종료”; 타이밍 오류를 확정할 증거가 없으면 늦었다고 단정하지 않음 |
| 미사용 승리 | 기본 공격만으로 이겨도 임무는 성공. 기술 증명만 미완료로 안내 |
| 종료 | 원하면 같은 현장에서 한 번 더 연습. 정답 사용을 위해 이미 이긴 본편 전투 강제 재수행 금지 |

기술의 효과를 분리해 확인하는 내부 비교는 동일 스탯 스냅샷으로 별도 수행한다. 실제 사용자 체험에서 성장을 제거하지 않는다. 수치 상승·전투 학습·새 기술의 기여를 구분하지 않은 시간 단축을 전부 새 기술 효과라고 해석하지 않는다.

## 07. 기본 전투 개선 — 입력·예고·후속 기회

| 요구 ID | 수정 내용 | 초기 값/검수 |
| --- | --- | --- |
| CB01 | 예고 시작·발동·후딜을 색 외 형태와 동작으로 분리 | 초기 전용 정예 예고1.2초·후딜0.8초 가설. 기존 전체 적 일괄 변경 금지 |
| CB02 | 실제 대응 성공에 짧은 정지·강조 효과 | 정지50~70ms 후보. 연속타마다 재발동 금지; 저효과 옵션에서는 약화/생략 |
| CB03 | R의 강화 가능과 실제 사용 가능 분리 | 충전 있음/쿨 대기/자원 부족을 각각 표시 |
| CB04 | 기본 공격이 강화 기회를 소비하면 표식 즉시 제거 | Q 성공→J 소비 후 R 강화처럼 오표시 금지 |
| CB05 | 실패 이유를 가능한 증거 범위에서 안내 | 쿨·자원·범위·시야·효과 만료를 구분 |
| CB06 | 공격 방향과 실제 판정 일치 | 화려한 이펙트 외곽을 실제 사거리로 오인하지 않게 표현 |
| CB07 | 다음 대응까지 위치 판단이 남게 구성 | Q 연타만으로 무적 유지 불가; 빈틈에 공격하거나 재배치 |
| CB08 | 시간 진행 기준 일원화 | 정지·대화·메뉴 동안 효과/예고/쿨타이머가 서로 다르게 흐르지 않음 |

현행 규칙에서 특히 주의할 점

현실 파문 흡수 창은0.7초, 성공 뒤 강화는4초이며 수동 기본 타격 또는 후속 기술에 의해 소비될 수 있다. 잔영 성공 강화는3초다. 현재 파문 R 쿨은5초이므로 Q 성공 직후 R이 항상 가능한 것은 아니다. HUD는 남은 강화 시간과 쿨을 함께 조회한다. 이번 MVP에서는 이를 숨기려고 쿨을 자동 초기화하지 않는다.

기술창·HUD의 “사용 가능”은 조건부 강화와 다르다. 일반 R도 사용 가능할 수 있지만 강화 R은 보관 충격·대상·시간 조건이 맞아야 한다. 유효 대응 표시는 버튼 입력 이벤트가 아니라 실제 전투 효과 이벤트에서 발생한다.

## 08. 적 구성·자원·난도 조정 방법

전용 프로필의 목적은 고정된 기본 공격만 반복해도 전투가 끝나는지, 대응 기술을 사용했을 때 의미 있는 이득이 생기는지 비교하는 것이다. 보스 HP를 임의로 크게 올려 기술 사용을 강요하지 않는다.

| 역할 | 행동·배치 | 기술 활용/기본 해법 |
| --- | --- | --- |
| 압박 | 가까이 오며 짧은 공격; 강타 예고와 첫 접촉 분리 | 기본 공격으로 밀어내거나 이동해서 분리 |
| 강타 정예 | 직선 접근→명확한 강타→후딜 | 파문 받아내기 / 잔영 이탈 / 봉인 예고 차단 / 기본 회피 |
| 사격 | 측면에서 고정 예고선; 엄폐와 시야 적용 | 먼저 접근해 제거하거나 앞의 정예와 위치 분리 |
| 응용 정예 | 강타와 사격 상황을 순차 변경 | 같은 적에게 하나의 정답 기술만 강요하지 않음 |

튜닝 순서: 예고 가독성→입력 반응→접촉/효과 정확성→공격 기회→HP/피해→회복·자원 순서. 손맛 문제를 공격력 보너스로 덮지 않는다. 비교 현장 수치 변경은 E1/E4에 동시에 적용하고 profileVersion으로 기록한다.

자원은 Q→R을 한 번 시도하고 실패해도 재시도할 여지가 있어야 한다. 첫 실험에서는 기존 최대 자원·회복·기술 비용을 유지한다. 고갈 때문에 학습이 멈추는 사례가 반복되면 시작 회복 지점을 조정하고 그 변경을 별도 비교한다. 무한 자원으로 만든 테스트 결과를 일반 플레이 결과로 보고하지 않는다.

기능 인수: 기본 공격·회피만으로도 숙련된 테스터가 완료할 수 있어야 한다. 재미 인수: 기술 활용이 단순 시간 단축 외에 안전한 공격 기회·위치 이득·위험 취소 중 적어도 하나를 분명하게 제공해야 한다.

## 09. E5~E6 인정 — 결과 보고에서 결정권으로

인정은 실제 현장 완료와 유효 대응 증거가 있을 때 발생한다. 임무만 성공한 경우는 전투 성과를 인정하되 “새 기술을 완전히 익혔다”는 대사를 쓰지 않는다. 직접 보고하지 않았다면 서린의 지식은 갱신하지 않는다.

| 단계 | 현재/제안 동작 | 상태·피드백 |
| --- | --- | --- |
| 보고 | 현장 완료+실제 효과를 서린에게 전달 | 능력 확인; 공식 등급은 자동 상승하지 않음 |
| 역할 | 기존 초동 대응 역할과 연결 | 이미 획득했다면 새 역할처럼 중복 공지하지 않음 |
| 판단 | 다음 현장의 우선 처리2안 중 선택 | 선택 상세 조회와 확정 분리 |
| 실행A | 사격 지원 차단 우선 | 사격 위협1개 비활성; 방어 안전 영역 추가 없음 |
| 실행B | 회수 통로 확보 우선 | 표시 영역 내 피해25% 감소 가설; 사격 적 유지 |
| 결과 | 동일 정예전에서 선택 효과 확인 | 처치 뒤 임무 결과와 선택 기여를 한 줄로 표시 |

초기 선택은 새 능력 구매가 아니라 협력 배치의 제안이다. 도겸은 정해진 후방 위치·전후 표식으로 역할을 보여 주며 길찾기 AI를 추가하지 않는다. 두 선택 모두 완료 가능하고 사건 결말·기연 소유권은 같다. 안전 영역은 무적이 아니며 상시 HUD에서 범위와 적용 여부를 표시한다.

대사 초안

도겸: “이번에는 네가 통로를 열었네. 회수는 내가 마무리할게.”서린: “보고와 현장 기록이 맞아. 다음 진입은 네 의견부터 듣자. 옆 사격을 줄일까, 회수 통로를 먼저 지킬까?”유효 대응이 없었다면: “현장은 잘 마무리했어. 새 대응은 다음에 더 확인해 보자.”

기존 first-response 보급2개를 사용하는 경우 reports.supplies의 같은 지급 ID를 재사용한다. 새 모드 완료금·별도 역할 포인트는 없다. 인정이 반복 보상 파밍으로 바뀌지 않게 한다.

## 10. 세 계열 확장·후속 장·보고 압축

| 계열 | E4에서 비교할 변화 | E6에서 얻는 이득 |
| --- | --- | --- |
| 파문 | 물러나던 강타를 흡수하고 반격 | 전방에서 적의 강타 후 공격 기회 확보 |
| 잔영 | 예고선 이탈 후 사격 위치로 접근 | 지원 적을 먼저 제압해 압박 분리 |
| 봉인 | 위험 예고를 취소해 안전하게 공격 | 강타·재생 시점 통제; 무한 봉쇄 방지 |

세 계열의 목적과 완료 조건은 같게 두고, 증명에 필요한 실제 효과만 다르게 한다. 잔영에 파문 받아내기를 요구하거나 봉인 없는 빌드에 재생 억제를 필수로 요구하지 않는다. 파문이 더 안정적이고 잔영이 더 빠를 수는 있으나 모든 조건에서 한 계열이 우월하면 전장을 조정한다.

후속 장 적용은 검증 뒤

4장: 구조한 사람이 이후 운송 지식으로 도움을 준다. 5장: 진화의 동작 변화와 현실 적용을 회수한다. 6장: 심화로 실제 재생 문제를 해결한다. 7장: 초반의 작은 결정권이 공동 대응 준비로 확장된다. 8~10장: 준비 결과가 보스의 지원·충전을 제한한다. 매 장 귀환 결과창·비교 전투를 반복하지 않는다.

왕복·보고의 피로 줄이기

보고를 삭제해 정보가 자동 전달되게 하지 않는다. 같은 NPC가 연속으로 요청하는 단순 확인은 한 대화 안의 두 구간으로 합치되 사건 상태는 각각 기록한다. 보고만을 위한 추가 왕복은 원래 귀환 동선에 배치한다. 보고마다 새 정보·관계 변화·결정·보상 중 무엇이 있는지 표기하고 아무 변화도 없으면 축약 후보로 삼는다.

## 11. 상태·임무 모드·저장·이행 계약

이 장의 이름은 구현 제안이다. 현재 존재하는 필드로 표현하지 않는다. 신규 컨트롤러 return-proof.js가 읽기 모델과 전이를 소유하고 UI는 영구 플래그를 직접 쓰지 않는다.

| 제안 데이터 | 용도 | 규칙 |
| --- | --- | --- |
| worldState.returnProof.version | 스키마 버전 | 초기1; 현재 save-v10과 별개 하위 버전 |
| baselineCompleted | E1 완료 | 기술 미보유를 뜻하지 않음; 표본 적격 별도 |
| proofCompleted | E4 현장 완료 | 기술 효과 증명과 독립 |
| verifiedFamily | 현실 유효 대응 계열 | ripple/echo/seal 중 증거 있는 값만 |
| reported | 서린에게 직접 보고 | proofCompleted와 verifiedFamily 선행 |
| roleChoice | A/B 선택 | reported 이후1회 확정; 같은 시도 도중 교체 불가 |
| applicationCompleted | E6 완료 | roleChoice 선행 |
| proofRuntime | 모드·적·입력 보호·타이머 | 일시 상태. 본편 스냅샷과 분리 |
| testTelemetry | 테스트 관찰 로그 | 제품 영구 보상 판정의 입력으로 사용하지 않음 |

현재 comparison:true는 XP·숙련 등과 실제 효과 등록에 영향을 줄 수 있으므로 아무 표식이나 재사용하지 않는다. 전용 모드는 일반 적 처치 보상·숙련을0으로 처리하되 실제 유효 대응을 검증 전용 훅으로 받을 수 있게 한다. 테스트 중 현실 기술 settled를 정상적으로 진행시키려면 검증된 효과 경로를 명시하고 가짜 보스 처치를 만들지 않는다. verifiedFamily는 활성 E4 임무의 실제 대상에서 발생한 효과만 인정하고, E2 연습·E1·일반 지역 효과를 가져오지 않는다. g.trial 플래그는 현실 유효성 검사와 충돌하므로 기존 시험 플래그를 무분별하게 재사용하지 않는다.

임무 중 저장은 시작 전 본편 스냅샷과 이미 확정한 영구 결과만 기록하고 중간 전투는 재시작한다. 효과 직후 저장과 현장 완료 후 저장에서 소유권·정착·원장 복원이 일치해야 한다. 임무를 나가면 당시 자원·소모품을 복원하는 무보상 시험 정책을 적용한다. 이 정책을 입장 상세에 명시한다.

구버전은 새 묶음이 없으면 미체험 상태로 시작한다. 기존 역할·기연·본편은 유지한다. 후기 저장에는 과거 E1 완료나 reported를 임의 생성하지 않는다. 저장 형식 번호는 착수 시 최신 번호를 확인하고 변경 파일만 원자적으로 이행한다. 로그 업로드는 기본 비활성이다.

## 15. 플레이테스트 — 모집·진행·질문

1차는 액션 RPG 숙련이 다른8명 정도를 목표로 한다. PC4명·모바일4명을 기본으로 하되 모집 상황에 따라 실제 구성을 기록한다. 이는 사용성 문제를 찾는 탐색 표본이며 유의성·전환율·시장 성공률을 추정하는 표본이 아니다.

## 17. 비교 실험·관찰 로그·결과 기록 양식

개선 효과를 구분하는 최소 비교

A는 현재 피드백, B는 개선 피드백으로 두고 적·능력치·기술 수치를 같게 한다. 별도 짧은 전투에서 절반은 A→B, 나머지는 B→A로 경험하게 하며 순서와 학습 효과를 기록한다. 같은 사람이 E1/E4를 순서대로 하는 서사 경험은 순서를 뒤집지 않는다. 소규모 결과를 인과관계 확정으로 표현하지 않는다.

| 로그/필드 | 필수 기록 | 사용 목적 |
| --- | --- | --- |
| 세션 | 익명 sessionId, build, device, 시작 저장, profileVersion | 재현·기기/숙련 분리 |
| 모드 | encounterId, E1/E4/E6, 시작/종료/실패/후퇴 | 구간별 소요·중단 |
| 기술 | castId, action, held, cost, cooldown, result | 수동/유지 입력과 실패 원인 |
| 효과 | targetId, absorb/evade/suppress, boost 생성/소비/만료 | 실제 대응·후속 활용 |
| 전투 | 피해·HP·자원·포션·적제압 | 체감 차이의 원인 |
| 상태 | 장착·정착·보고·선택·저장 오류 | 성장/인정 전이 확인 |
| 도움 | 개입 시점·이유·내용 | 자립 진행과 안내 효과 구분 |

로그는 검증용이고 보상을 지급하는 근거 데이터가 아니다. 전투 판정 원본에서 이벤트를 내보내며 UI 애니메이션으로 효과 성공을 추정하지 않는다. 매 프레임 좌표를 모두 저장하지 말고 중요한 사건 중심으로 기록한다.

| 실행일/빌드 | 검증 ID | 기기·저장 | 관찰값·발언 | 증거 | 판정/후속 |
| --- | --- | --- | --- | --- | --- |
| 미실행 | 예: F06/H2 | 실행 시 기록 | 기대 결과와 실제 결과 구분 | 영상/로그/메모 경로 | 통과/실패/보류 + 담당 |

결과 보고에는 유효 표본 수, 제외 이유, 기능 결함, 긍정/부정 발언, 실제 행동, 다음 수정1~3개를 담는다. 성공 장면만 편집하지 않는다. 기존 문서의 통과 수나 이전 빌드 결과를 복사하지 않는다.

## 18. 최종 인수·기획 자체 점검·근거

개선 완료 조건

기존 1~10장·세이브·기연 소유권·세계별 성장을 보존한다.

대표 계열에서 전후 변화→실제 활용→보고→역할 선택→현장 결과가 이어진다.

강제 실패·가짜 칭찬·동행 AI 없이 핵심 경험을 만든다.

기능 F01~F28에서 출시 차단 결함이 없다.

플레이테스트에서 성장과 인정이 실제 행동·자발적 설명으로 관찰된다.

판정 미달 항목과 후속 과제를 공개하고, 검증되지 않은 재미·사업성을 완료로 보고하지 않는다.

자기비판적 위험 점검
