# 쌍계 v1.1 전체 개선 적용 설계

작성일: 2026-10-02. 코드 기준: main 5898d75.
사용자 확인 범위: UI·성장 체감·전투 난도·6장 체득·음향·통합 던전 입구를 포함한 v1.1 전체 개선.
상세 요구사항: [첨부 원문 보존본](../../SSANGGYE_IMPROVEMENT_SPEC_v1.1.md).
이 문서는 구현 설계이며 구현 완료 기록이 아니다.

## 작업 조건

main에서 직접 작업한다. 기존 미추적 Unity·아트·참고 파일을 보존한다. 별도 브랜치·worktree를 만들지 않으며 푸시·배포는 이번 요청 범위에 포함하지 않는다. 현재 1~7장, 세계별 성장, 기존 저장 및 이전 보관판을 보존한다. 문서의 예시 수치를 이미 검증된 사실로 취급하지 않는다.

## 현재 코드와 차이

- chapter-six.js는 백련 대화에서 dualBreath를 즉시 부여한다. 적 전멸 후 재시도는 지역 전체를 다시 불러온다.
- encounter-director.js는 여러 후반 지역을 같은 단계로 계산하여 보스 체력 760·피해 30을 적용한다.
- world-achievements.js에는 지급 버전과 차액 정산이 없고 전승 자체의 신체 보너스가 없다.
- world.js 및 후속 장 모듈은 거점에 목적지별 입구를 추가한다. objective-model.js도 개별 입구로 경로를 계산한다.
- app.js는 짧은 합성음과 메모리상의 켜기/끄기를 사용한다. development-ui.js에는 성장·무공 외 여러 진입 버튼이 혼재한다.

## 선택한 구조

기존 실행 경로와 저장 모델을 확장하고, 공통 판정과 표현의 책임만 별도 모듈로 분리한다. 전체 엔진 교체는 범위에 비해 저장·보관판 위험이 크다. 기존 화면마다 개별 패치를 추가하는 방식은 입장 조건과 입력 차단의 중복을 남기므로 사용하지 않는다.

### 공통 UI

최상위 목적은 캐릭터·임무·기록·설정으로 정리한다. 캐릭터는 개요·성장·무공 3탭이다. 성장 첫 화면에 현재 심법/현실 운용과 경지 돌파를 표시하고 심법 심화는 기존 운용 카드에 포함한다. HUD는 생존·자원·기술·다음 행동을 우선한다.

공통 토큰·버튼·패널·단일 팝업 계층으로 이관하고 기존 CSS 중복 규칙을 제거한다. 화면별 선택·스크롤·읽음을 보존한다. UI 클릭·우클릭·터치 및 닫기 입력은 전장 행동으로 전달하지 않는다. 기존 키 변경을 존중한다. index.html, app.js, character-ui.js, development-ui.js, objective-ui.js, news-ui.js와 관련 CSS를 수정한다.

### 성장과 현실 역할

성취 원장에 보상 버전과 지급 내역을 둔다. 첫 기연 공통 신체 성장은 여정당 한 번 지급하며 추가 계열은 선택 폭을 확장한다. 기존 정산은 유지하고 증가분만 한 번 지급한다. 같은 현실 레벨에서 기본 공격 +20~30%, 생존 여유 +15~25%는 실험 목표로 사용하며 실제 확정값과 측정 조건을 별도 기록한다.

world-reports.js와 본편 사건에 초동 대응·구조 성과·공동 대응 역할을 연결한다. 실제 목표, 1회 보급, 마지막 전장 준비 중 해당 역할의 효과를 구현한다. 세 계열 모두 공통 완료 조건을 달성할 수 있게 한다. 공식 E급과 현장 자격을 분리한다. 새 화폐·반복 의뢰·동료 AI·공식 승급은 추가하지 않는다.

### 6장 체득과 7장 선택

관찰 → 기록 → 백련의 해석 → 임시 운용 → 실제 효과 성공 → 심법 심화 영구 체득 → 현실 증명 → 보고를 구분한다. 대화는 시도 기회를 열고, dual-breath.js 및 reality-skills.js의 유효 효과 사건으로 획득한다. 수련은 경험치·금화·숙련·반복 성취를 주지 않는다. 적 전멸과 과성장 시 잔류 파형으로 진행하며 전체 전투를 강제로 다시 하지 않는다.

기존 dualBreath 획득은 인정하고 재수련이나 가짜 과거 기록을 만들지 않는다. 기존 4초/8초 보조를 유지한다. 표시명은 심법 심화, 효과명은 연계 강화로 통일한다. 7장 기존 준비에 대피 통로/정예 차단 선택을 연결하여 현재 전장의 안전 구간 또는 선행 위협이 달라지게 한다. 보고와 NPC 지식은 실제 전달 이후 갱신한다.

### 전투와 음향

지역별 최종 전투 프로필을 하나의 데이터에서 산출한다. 초기 정예·무리는 예고와 위치 판단이 필요하고, 성장 후 같은 적은 자동 강화하지 않는다. 장별 적 수치·역할·보상·예고를 생성 결과로 검증한다. 세 계열×두 운용과 공격 유지/회피/기연 대응의 차이를 측정한다. 원문의 전투 시간은 가설이며 사람의 난도 평가와 구분한다.

음향 모듈은 확정된 시전·예고·명중·방어·회피·사망 사건을 소비한다. 시전 ID·타격 순번·대상·결과로 중복을 제한한다. 동시 재생 24개 중 중요 신호 4개를 확보한다. 기본 타격은 3~5종 변주하고 세계별 질감을 구분한다. 자체 합성 음원은 제작 방식과 사용 근거를 기록한다.

전체·배경음·전투·UI 음량과 음소거를 저장한다. 미리듣기는 전투 사건을 만들지 않는다. 사용자 조작 이후 재생을 준비하며 실패해도 게임은 계속한다. 일시정지·세계 이동·재도전에 예약과 반복 재생을 해제한다. 중요 예고의 시각 표현도 유지한다.

### 통합 던전 입구

지역 ID·세계·표시/해금 조건·입장 전제·재방문 정책·안전 귀환점을 공통 진입 데이터에 정의한다. 기존 gate/story-gate/later-gate 조건을 실제 수락·처치·보고 사건과 매핑한다. UI와 실제 입장이 같은 판정 결과를 사용한다.

city와 village에 던전 입구를 하나씩 둔다. 경계석·NPC·상점·던전 내부 사건 장치는 유지한다. 입구 상호작용은 목록 → 선택 → 상세 → 입장하기 순서다. 행 클릭은 이동하지 않는다. 잠김·새 해금·진행 중·보고 필요·재방문·현재 진입 불가를 구분한다. 미래 상세는 숨기고 다음 행동을 알려 준다.

입장 직전에 세계·입구 거리·조건을 재검사한다. 아트 준비 실패 시 기존 위치와 기록을 유지하고 재시도한다. 중복 요청을 막는다. objective-model.js는 다른 세계 목표를 경계석 → 상대 거점 → 통합 입구 → 목적지로 안내한다. 보고 단계에서는 NPC를 우선한다. 원격 출발·자동 이동·목록을 통한 세계 전환은 추가하지 않는다.

### 저장과 이행

save-v10.js에서 버전 있는 이행과 유효성 검사를 수행한다. 원본 백업과 실패 시 원본 보존을 적용한다. 기존 지역 ID·완료·해금·보고·구조 기록을 유지한다. 던전 안 저장은 유효하면 그 위치에서 이어 간다. 구 포털 참조는 통합 입구와 목적지 ID로 이관한다. 잘못된 위치만 같은 세계의 안전 지점으로 보정하고 이유를 알린다. 역할은 실제 완료 근거로만 복원한다. 이전 보관판은 별도 유지한다.

## 구현 순서와 검증

1. 기존 전투·화면·입력 기준을 수집하고 공통 UI 및 대표 입구를 연결한다.
2. 성장 원장·표시명·귀환 결과·현실 역할을 연결한다.
3. 행동 기반 6장, 7장 선택, 초기 전투 프로필과 기본 음향을 구현한다.
4. 세 계열·두 운용·1~7장 및 모든 던전으로 확장하고 저장 회귀를 확인한다.

자동 검증은 성취/보급 중복, 보고 전후, 6장 과성장·계열 변경·기존 체득, 지역별 최종 수치, 잠김 우회·이동 실패·던전 저장, 음소거·중단·중복 재생, 입력 누수·선택/스크롤 복원을 다룬다. 기존 Node 테스트와 브라우저 하네스를 확장한다.

화면은 360×640, 390×844, 844×390, 1280×720, 1920×1080 및 200% 확대를 확인한다. 원문 G/S/C/U/R/N/P/A 관문별 증거와 남은 제한을 기록한다. 실제 사람의 성장 인지·난도 평가와 실물 휴대폰·이어폰·스피커의 10분 청취, 저사양 성능은 해당 검수 없이는 완료로 표시하지 않는다.

전체 범위는 사용자 확인 완료. 구현 연결 설계는 검토 대기. 설계 확인 후 파일·인터페이스·테스트별 구현 계획을 작성한다.
